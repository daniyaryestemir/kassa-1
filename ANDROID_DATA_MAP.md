# Android Data Map

Этот файл описывает, какие данные уже есть в web/backend и как переносить их в Android по этапам.

## Общая идея

Android-приложение не должно копировать HTML сайта.
Оно должно брать данные из backend API и показывать их в мобильном интерфейсе.

Схема:

`Android app -> Flask API -> MySQL`

## Что уже есть в backend

Готовые API:

- `GET /api/dashboard`
- `GET /api/kassa/products`
- `POST /api/kassa/checkout`
- `GET /api/nomenklatura`
- `GET /api/postupleniya`
- `GET /api/postupleniya?uuid=...`
- `GET /api/otchety`
- `GET /api/barcode-print-queue`

## Этап 1. Только чтение данных

На первом этапе Android должен просто показать данные сайта.

### 1. Главная

Источник:

- `GET /api/dashboard`

Что вытаскиваем:

- продажи за сегодня
- количество чеков
- количество товаров
- количество поступлений
- очередь печати
- товары с малым остатком
- последние поступления

### 2. Номенклатура

Источник:

- `GET /api/nomenklatura`

Что вытаскиваем:

- список товаров
- название
- остаток
- закупочная цена
- розничная цена
- оптовая цена
- категория
- штрихкоды

### 3. Поступления

Источники:

- `GET /api/postupleniya`
- `GET /api/postupleniya?uuid=...`

Что вытаскиваем:

- список поступлений
- контрагент
- дата
- суммы
- состав поступления

### 4. Отчеты

Источник:

- `GET /api/otchety`

Что вытаскиваем:

- фильтры по датам
- продажи
- прибыль
- наличные
- карта
- долг
- товарные строки

### 5. Очередь печати

Источник:

- `GET /api/barcode-print-queue`

Что вытаскиваем:

- задания на печать
- статус
- количество копий
- дата создания

## Этап 2. Касса

Источники:

- `GET /api/kassa/products`
- `POST /api/kassa/checkout`

Что делаем:

- поиск товара
- добавление в корзину
- выбор типа продажи
- выбор способа оплаты
- отправка продажи в backend

## Этап 3. Создание и редактирование

На этом этапе начинаем не только читать, но и менять данные.

Что можно добавить позже:

- создание поступлений с Android
- редактирование номенклатуры
- быстрый товар
- контрагенты
- очереди печати с созданием заданий

## Приоритет переноса

Самый правильный порядок такой:

1. `Главная`
2. `Номенклатура`
3. `Поступления`
4. `Отчеты`
5. `Очередь печати`
6. `Касса`

Почему так:

- сначала подключаем стабильное чтение данных
- потом добавляем продажу
- потом уже редактирование и создание
